# Access matrix

Generated by `python manage.py role_matrix`. Do not edit by hand - regenerate it, or it will
drift from the code it claims to describe. A test compares this file with a fresh run, so a
permission change that is not reflected here fails the build.

**Y** the role holds the permission. **.** answers 403. **o** any signed-in user, with the
records themselves scoped inside the view. **\*** no sign-in needed.

A **Y** means the role holds the permission the view declares, which is necessary but not
always sufficient. Where the **Also enforced** column names a further limit, the view applies
it to the records themselves: a teacher holding `attendance.view_leaverequest` opens the leave
list and sees only their own requests, and a staff member opens their own file and no one
else's. That column is declared by each view rather than inferred, so it cannot quietly drift
from what the code does.

The endpoints open without signing in are marked **\***: a download whose audience is Public,
the pages that verify a report card, a certificate or a transcript, the result lookup, the
payment gateway's return, a school's online admission pages and the health probe. A test
asserts that list, so a view that forgets its permission decorator cannot quietly join it.
